MODIF 500 - Photos HEIC/HEIF : extension + fil d'actualite
================================================================================
Date : 2026-06-15

## Symptome
Upload photo iPhone depuis le compositeur du fil :
" Impossible de convertir cette photo HEIC/HEIF. "

## Cause
1. Fichiers iOS/iCloud souvent sans extension `.heic` / `.heif` ni MIME fiable.
2. `heic2any` / libheif echoue sans nom de fichier reconnu.
3. Le fil passait le fichier brut a l'editeur (pas de `prepareImageFile` avant ouverture).
4. Validation synchrone rejetait les HEIC detectables uniquement par en-tete binaire.

## Correctifs
- `normalizeHeicFileMetadata` : ajoute extension + MIME avant conversion.
- `sniffHeicMagicBytes` : scan marques compatibles ftyp (32 octets).
- `validateImageFileAsync` : accepte HEIC sans extension/MIME.
- `convertHeicToJpegFile` : candidats `File` nommes (plus seulement `Blob` type).
- Fil (`ActualiteTabPage`) : `prepareImageFile` avant editeur, etat " preparation ".
- `loadImageBitmapFromFile` : validation async unifiee.

## Fichiers
- app/src/lib/imageConstraints.ts
- app/src/lib/imageConstraints.heic.test.ts
- app/src/lib/imageUtils.ts
- app/src/lib/profileImageProcessing.ts

MODIF 486 - Création salon plus rapide (GPS, verify, probe cache)
================================================================================
Date : 2026-06-14

## Symptôme
Création de salon lente : enchaînement séquentiel GPS (12 s) ? verify-access Spotify
? POST /salons (re-probe session) ? load-playlist (résolution API externe) ? copie lien
invitation, modal bloquée jusqu'à la fin.

## Goulets identifiés
1. **GPS** : `enableHighAccuracy` + timeout 12 s avant tout appel API.
2. **verify-access** : appelé pour toutes les playlists Spotify, y compris celles déjà
   listées via `/me/playlists` (redondant avec load-playlist).
3. **load-playlist** : bloquait fermeture modal + navigation (YouTube + Spotify).
4. **probeSpotifyHostSession** : répété sur status, verify, create, load-playlist (~4×).
5. **getPlatformStatus** : re-fetch à chaque ouverture modal sans cache court.
6. **Lien invitation** : `getSalonShareUrl` + `copyShareLink` synchrones après create.

## Correctif
### Frontend
- `salonCreateFlow.ts` : GPS rapide (5 s, cache 2 min, sans high accuracy) ;
  skip verify si playlist bibliothèque (`playlistId` sans URL) ; `deferSalonPlaylistLoad`.
- `CreateSalonModal.submit` : `Promise.all` position + verify (URL seulement) ;
  create ? fermeture immédiate ? playlist en arrière-plan (socket `salon_updated`) ;
  copie lien invitation non bloquante ; prop `onDeferredError` pour toast erreur load.
- `platformStatusCache.ts` : cache TTL 25 s sur GET `/platforms/status` ;
  invalidation sur `dispatchPlatformStatusRefresh`.
- `HomePage` : `onDeferredError={setToastMsg}`.

### Backend
- `spotifyPlaylists.ts` : cache probe session hôte 20 s (succès uniquement) pour éviter
  3–4 appels `/me` Spotify pendant le flux create.

## Nouveau flux submit (playlist Spotify bibliothèque)
1. GPS + create en parallèle (pas de verify).
2. Modal fermée, navigation salon.
3. load-playlist en background ? queue via WebSocket.

## Nouveau flux submit (playlist URL externe)
1. GPS ? verify-access (pré-vol léger metadata).
2. create ? fermeture ? load-playlist background.

## Gain attendu
- **Morceau / sans playlist** : ~1–5 s (GPS + create seuls, vs 12 s+ avant).
- **Playlist bibliothèque** : ~0,5–2 s perçu (modal fermée après POST /salons) ;
  queue visible quelques secondes après via socket (charge API hors chemin critique).
- **Playlist URL** : verify ? GPS économise 1–3 s ; load-playlist n'ajoute plus 3–15 s
  au spinner modal.
