MODIF 479 — Refonte flux création salon Spotify + playlist (structure + fix définitif)
================================================================================
Date : 2026-06-13

## Symptôme (persistant après MODIF 478)
Création salon Spotify avec playlist : toast « Forbidden » ou « Session expirée »
alors que /me/playlists listait les playlists. Logs prod :
  [spotify-playlist] API error { status: 403, detail: 'Forbidden', context: 'resolveSpotifyPlaylistTracks' }

## Cause racine (vérification complète)
1. **Faux positif oauthScopes** : à l’OAuth initial, `tokens.scope || SPOTIFY_SCOPES`
   enregistrait tous les scopes même non accordés → probe DB OK, API /tracks 403.
2. **Probe session incomplet** : `/me` + scopes stockés suffisaient ; `/me/playlists`
   peut réussir sans accès réel aux morceaux (`/playlists/{id}/tracks`).
3. **403 bare Forbidden mal classé** : si scopes DB « OK », renvoyait `spotify_token_expired`
   au lieu de `spotify_scope_missing` → message trompeur, retry inutile.
4. **Scopes playlist partiels** : un seul scope (private OU collaborative) suffisait ;
   playlists mixtes → 403 selon le type choisi.
5. **Duplication frontend** : CreateSalonSpotifyPlaylistPicker et SalonSpotifyPlaylist
   dupliquaient chargement session, codes reconnect, mapping erreurs, retry load-playlist.
6. **Salon créé avant échec load** : pas de pré-vol → salon vide si load-playlist échoue.

## Correctif structurel

### Backend — modules partagés
- `spotifySession.ts` : codes auth, `spotifySessionFailureMessage()`, `respondSpotifySessionAuthFailure()`
- `spotifyPlaylistErrors.ts` : `SpotifyPlaylistError`, `throwSpotifyPlaylistApiError()`
- `spotifyPlaylists.ts` : refactoré (format propre), probe live `/tracks?limit=1`,
  `verifySpotifyPlaylistTrackAccess()`, invalidation scopes sur 403 bare
- `spotifyOAuth.ts` : plus de fallback `SPOTIFY_SCOPES` ; les deux scopes playlist requis ;
  `invalidateStoredSpotifyOAuthScopes()`
- Route `POST /platforms/spotify/playlists/verify-access` (pré-vol avant création)
- Routes `load-playlist`, `POST /salons`, `verify-access` : réponses auth unifiées

### Frontend — source de vérité
- `lib/spotifyPlaylistSession.ts` : codes reconnect, i18n, `toSpotifyPlaylistRef()`,
  `translateSpotifyApiError()`, `translateSalonCreateError()`
- `hooks/useSpotifyPlaylistLibrary.ts` : bibliothèque + session + verify + reconnect
- `components/SpotifyPlaylistPickerFields.tsx` : UI partagée (select, URL, erreur, reconnect)
- `CreateSalonSpotifyPlaylistPicker`, `SalonSpotifyPlaylist` : utilisent hook + champs partagés
- `CreateSalonModal` : verify-access **avant** createSalon ; plus de retry load-playlist inutile

## Symptôme
Après MODIF 477 : toast **« Impossible de charger la playlist — Forbidden »**
au chargement/sélection playlist (CreateSalonModal ou SalonPage).

## Cause racine
1. Spotify renvoie souvent 403 avec message brut `Forbidden` (pas
   « insufficient client scope ») sur `GET /playlists/{id}/tracks`.
2. MODIF 477 a correctement cessé de classer ce 403 en `spotify_token_expired`,
   mais `throwPlaylistApiError` affichait encore le détail brut dans le toast.
3. Comptes liés **avant** l'ajout des scopes playlist (`playlist-read-private`,
   `playlist-read-collaborative`) : `oauthScopes` vide ou incomplet →
   `probeSpotifyHostSession` laissait passer (garde `if (storedScopes && …)`),
   `/me/playlists` pouvait lister, `/tracks` échouait en 403 Forbidden.
4. `userNeedsSpotifyScopeReconnect` ne vérifiait pas les scopes playlist.

## Correctif
### Backend
- `isSpotifyBareForbiddenError` : détecte 403 sans détail explicite.
- `getMissingSpotifyPlaylistReadScopes` : scopes manquants si `oauthScopes` vide.
- `probeSpotifyHostSession` : échec `spotify_scope_missing` si scopes absents
  ou playlist-read manquants ; 403 bare → scope_missing.
- `resolveSpotifyPlaylistTracks` : pré-vol scopes + mapping 403 Forbidden
  → `spotify_scope_missing` (scopes manquants) ou `spotify_token_expired`
  (après refresh) ; plus de suffixe brut « Forbidden ».
- `spotifyFetch` : pas de retry refresh si scopes playlist manquants.
- `userNeedsSpotifyScopeReconnect` : inclut scopes playlist.

### Frontend
- Messages FR dédiés playlist (`errorPlaylistScopeMissing`, `errorPlaylistForbidden`).
- Retry load-playlist sur `spotify_scope_missing` / `spotify_playlist_forbidden`.
- Bouton reconnecter sur `spotify_playlist_forbidden`.
