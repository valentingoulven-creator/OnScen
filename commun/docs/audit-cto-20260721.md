## 2. Bugs et régressions trouvés

### BUG-A (🔴 nouveau) — Double exécution de callback via `?? `

```585:585:c:\Dev\Soundy\web\app\src\components\NearbyPeoplePanel.tsx
eventsBrowse?.onOpenEvent?.(post) ?? eventsBrowse?.onOpenEventDetail?.(post);
```

`onOpenEvent` retourne `void` → toujours `undefined` → l'opérateur `??` déclenche **systématiquement** aussi `onOpenEventDetail`, même quand `onOpenEvent` a réussi. C'est exactement le bug corrigé cette semaine dans `EventCardMapSidebar` (« le `??` fallback ouvrait le modal car zoom retourne `undefined` », MODIF 1064) — **le même anti-pattern existe encore ailleurs**. Recommandation : grep systématique `\?\.\(.*\)\s*\?\?` sur le repo et remplacer par des `if/else` explicites ou un helper `callFirst(fn1, fn2)`.

### BUG-B (🟠) — Hook React appelé après un early return

```139:171:c:\Dev\Soundy\web\app\src\components\EventCard.tsx
if (isSidebar && isCarousel) {
  return (
    <EventCardMapSidebar post={post} onOpen={onOpen} onPostChange={onPostChange} />
  );
}
// ... 25 lignes plus bas ...
const resolvedLocationCoords = useMemo(() => { ... }, [locationCoords, post.eventLocation]);
```

Violation de `react-hooks/rules-of-hooks` (erreur ESLint, pas warning). Si `density`/`layout` changent entre deux renders du **même** composant monté (peu probable mais possible si un parent change ces props sans démonter), React lèvera « Rendered fewer hooks than expected ». Fix : déplacer `resolvedLocationCoords` (et tout hook après lui) avant le `if`.

### BUG-C (🟡) — Tests backend cassés : `pgSalonsLives.hydrate.test.ts`

```
FAIL src/lib/pgSalonsLives.hydrate.test.ts > getSalonFromStore > hydrate un salon actif absent de la RAM
TypeError: Cannot read properties of undefined (reading 'rows')
FAIL ... > retire un salon fantôme RAM si PostgreSQL le marque inactif
Error: Test timed out in 5000ms.
```

Le mock du client PG ne retourne pas la forme attendue (`{ rows: [...] }`). Ce test couvre exactement le mécanisme d'hydratation salon multi-worker PM2 documenté dans `STACK-CIBLE.md` — **une régression silencieuse ici est dangereuse en prod cluster**. À corriger avant le prochain déploiement multi-instance.
